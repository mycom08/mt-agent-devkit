# Dev Implement

**Requires:** `dev-core`, `raise-question` (questions), `git-workflow` (branch and status), `comment` (before any comment)

Task skill for a story implementation spawn. Do the steps in order; none is optional.

## Before Starting a Story

1. **Read the story in full** before writing any file, whatever its status: User Story, every Acceptance Criterion, Technical Scope and every linked technical doc.
2. **Read every existing comment** on the GitHub Issue; PO and TL may already have added context.
3. **Read every existing file the story modifies or appends to.** Note stale placeholders, forward references and superseded instructions the change will make wrong, and fix them in this story, not as a separate task.
4. **Raise questions and wait:** `raise-question` section 2. Do not begin until every blocking question has a confirmed PO or TL answer.
5. **Design first** when the story is complex (new workflow stage, major template restructure, new devkit command, or a breaking change to `init project` behavior): post a design as an issue comment tagging TL. Proceed only after TL replies with the exact phrase **"Design approved"**.
6. **UI prototype reference:** only for a repo generated by Build Software's UI-bearing companion-repo convention, read `.mt-agent-devkit/rules/UI_Prototype_Rules.md` before implementing a screen with a `-ui-prototype` counterpart. It does not apply to the devkit's own Markdown-only repo.

## Start

7. Run branch preflight `create` from the immutable Base Branch and full Base/Remote Base SHAs, then move the story to `in-progress` and verify the branch (`git-workflow` section 1). A BLOCKED preflight stops for direction.
8. Implement. Load each point-of-use skill in the `dev-core` load map right before its action, even if you read it earlier in the session.
9. A question that surfaces mid-implementation: `raise-question` section 3 (post the question, report, pause).
