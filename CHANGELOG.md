## [Unreleased]

### Fixed (v0.1.42 — Commenter gate: the issue-comment cap becomes enforceable)
- [ST-000038] Issue comments were the only capped agent artifact with no enforcement behind the cap. `Story_Standard_template.md` §12 gains a third gate — **Commenter — Before Posting an Issue Comment** — alongside the existing Implementer and Reviewer gates. Its load-bearing item is a `wc -w` ≤ 200 self-check, doing for comments what the `wc -c` ≤ 10,000 check already does for memory files. QA's per-AC evidence exemption is carried through as a *stated* exception (noted in the comment), not a silent skip.
- [ST-000038] `Story_Standard_template.md` §9 writing rules — three deltas, each closing a case where the observed overage was consistent with the rules as literally written: (1) **one topic per comment** promoted out of the threading block into numbered rule 2, phrased as a constraint on composition rather than on reply location, with an explicit carve-out that batching replies to questions asked *together* is permitted and what's prohibited is an unasked finding smuggled into an answer; operational argument stated — a multi-topic thread leaves `Thread Status` with no coherent value. (2) rule 4 now prohibits pasting command output, check transcripts, or verification logs, where it previously only stated "evidence by pointer" as a principle — scoped explicitly to issue and PR comments alike, with a single named carve-out, **gate-mandated CI evidence**: the literal `gh pr checks <PR-number>` output the §12 Reviewer gate requires in a PR approval comment. The §12 Reviewer gate and the new Commenter gate each name the carve-out from their own side, so the prohibition and the approval mandate can both be obeyed. (3) new rule 5 **body edits are announced, not reproduced** — the closer-role failure mode: a comment that restates the AC wording it just wrote into the body creates a second copy that goes stale on the next edit and then contradicts the body. The argument is staleness, not word count.
- [ST-000038] `Agent_Common_template.md` §2 rule 4 ("Point, don't mirror") scoped to issue comments as well as memory-file writes — re-deriving an already-recorded fact costs more in a comment, which every downstream role on the story re-reads.
- [ST-000038] All four per-role views (`Story_Standard_Dev/PO/QA/TL_template.md`) carry the same delta in their condensed writing-standard lines, each phrased for its role's actual failure mode — PO gets the announce-don't-reproduce rule with a worked example (it is the only role that edits the story body), TL gets the mid-review-finding case, QA keeps its evidence exemption with the scope clarified (exempts the cap only, not the one-topic or transcript rules). The Dev and TL views additionally carry the gate-mandated-CI-evidence carve-out, since both act as PR reviewers; the PO and QA views do not, because neither approves a PR and so neither can encounter the conflict. Without this the views drift from the cross-role source they restate.
- [ST-000038] `Strict_Mode_Story_Guide_template.md` — ripple site not named in the AC, found by grep: its local comment-entry writing standard restates §9 verbatim for strict mode and would have drifted. Same delta applied; the Commenter gate is declared applicable with "issue comment" read as "comment entry", and the transcript carve-out is noted as inapplicable — strict mode has no PRs, so nothing is exempt there.
- [ST-000038] Comment **format** skeleton (header / Thread Status / Area / Decision / Next) deliberately unchanged — it was correct in every observed case. Auto-enforcement (a CI hook running `wc -w`) deliberately out of scope; the gate is a self-check, matching how the memory-file cap works.
- [ST-000038] The gate gained a **drafting target**, because the first version induced the waste it was meant to prevent. A post-hoc `wc -w` check makes the natural workflow draft-then-truncate, and at working context every truncation pass re-reads everything: measured on a real agent run, one 200-word comment took four rewrites (272 → 213 → 200) and cost **22% of that entire run** — more than the diagnosis phase that located every edit site in the story. §9 rule 3 now leads with the shape (one short paragraph per topic — decision, one-line why, pointer), states that the `wc -w` check is a backstop that should almost never fire, and directs a failing count to the *cause* rather than to compression: an over-length draft is usually a bundled second topic (rule 2) or a pasted transcript (rule 4), and both are fixed by removing something whole. §12's Commenter gate splits accordingly into one **before you draft** item and the existing **before you post** checks. Per-role views carry the target in their own shape — QA's is one line per AC (criterion, verdict, pointer), so its length follows AC count and never needs trimming at all.
- [ST-000038] Source: community retro contribution Issue #106 (+ its follow-up comment adding the closer-role delta). The drafting-target gap was found by measuring the token cost of the agent runs that implemented and reviewed this story, not from the original contribution.
