## User Story

> As a **devkit maintainer**,
> I want **one common `comment` skill that owns the comment template, writing rules and Commenter gate for every agent role**,
> So that **roles stop carrying duplicated comment rules, agents load them on demand, and the standard is changed in one place**.

## Acceptance Criteria

- [ ] A new shared skill `comment` exists (canonical `.mt-agent-devkit/skills/comment/SKILL.md`) and owns: the comment template and Thread Status, writing rules (decision-first, one topic, length cap and draft-to-shape, evidence by pointer, delta-only corrections, no comments about comments, one close-out), the `@` and bare `#` prefix bans, the announce-not-reproduce body-edit rule, the Commenter gate, and the `gh pr checks` Reviewer-gate carve-out.
- [ ] The skill is registered like `agent-security`: provider discovery stubs (`.claude`, `.antigravity`, `.codex`), the distribution template, `SHARED_SKILLS` in `build_bundle.py`, read-routing, migration inventory and the Read Manifest. A target synced from an older version installs it cleanly.
- [ ] `Story_Standard.md §9`/`§12` (Commenter part) and the per-role `Story_Standard_*.md §9` sections point to the skill instead of repeating its rules. `Developer_Rules_Read_On_Demand.md §20` is reduced to Dev-only notes and the Developer routing row loads the skill.
- [ ] Role-specific comment rules remain only where a role has a case others lack (TL inline PR comments plus Issue notify; QA per-AC report and cap exemption; Dev/TL peer-review CI paste; PO same-pass body update). BA and UI/UX carry none.
- [ ] `po-comment` is reduced to PO-only content that requires `comment`, or retired with its PO rules moved to `po-write-story`; every reference (orchestrator PO table, PO skills, read-routing) is updated consistently.
- [ ] Existing template and routing tests pass, and a test asserts each role's comment route resolves to the `comment` skill.

## Technical Scope

Analysis: comment rules are ~90% identical across PO, TL, Dev, QA, UI/UX and BA; only the points in AC4 differ. Canonical skill text lives under `.mt-agent-devkit/skills/`; provider stubs are 333-byte pointers; the distribution template is the copy synced to targets. Check `read-routing.json` and the Read Manifest for `Developer_Rules_Read_On_Demand.md §20` references before editing it. Verify `RETIRED_SURVIVORS` handling for a non-PO shared skill (`agent-security` is the precedent).

Out of scope: the orchestrator inline-PO over-loading fix (separate story).
